# Merge note — the repo's live main with the Playground branch (23 Sep 2026)

What happened: GitHub `main` (39 commits on 23 September, the version that is live) was merged into the local branch
that carried the Playground, the kits and the polish phases (21 commits). The branch is `merge/repo-main-with-playground`;
its merge commit has `origin/main` as a parent, so pushing it moves `main` forward without rewriting anything.

## The rule used

Where both sides changed the same behaviour, **the live behaviour wins**. What only this branch added comes in where it
does not change what a live player sees in the flows `task.md` lists, or is needed by the Playground and the kits.
Every decision below was checked against the running build (see Verification).

## Decisions, file by file

- **Camera** (`src/ceritera/game/camera.ts`, `src/fair/engine.ts`): the repo's, whole. Hall-only collision, quick
  in / gentle out, no wider view on a run, rest at 6.4 m and pitch 0.38. Dropped from this branch: the five-ray
  collision whiskers and the view that turned behind the body on its own (both would bring back the "camera moves by
  itself" complaints the repo fixed on 23 September).
- **Walking and the trail** (`src/fair/engine.ts`): the repo's. The route list, the guide's jogging pace, Pause /
  Resume / Stop, the trail from checkpoint to checkpoint on `CHECKPOINT_ORDER`, arrival at 6 m of path, the reached
  list, the beams. Dropped from this branch: its route follower (`src/fair/route.ts` and its test, deleted) and its
  trail target and arrival rules.
- **Which booth you are at** (`proximity` in `src/fair/engine.ts`): the repo's rule (nearest booth centre within
  `STAMP_RADIUS_M − 0.6`). This branch's open-side rule was tried first and failed the side-by-side run: the guide stops
  beside UOB's side partition, where the repo shows Scan now, the booth card and Swap card; the open-side rule credited
  the neighbouring booth instead. Kept from this branch only for **tapping a booth**: the body walks to the booth's open
  side (`reach.approach`, falling back to the nearest walkable spot), which the repo's rule counts as at the booth.
- **Toasts** (`src/ui/App.tsx`, `src/ui.css`): the repo's column under the mission card. This branch's measured
  placement (`--hud-b`) is gone; its offline banner and the Playground's run card sit in the same column.
- **Mission card, sheets, menu, card form, scan** : the repo's. Kept from this branch: keyboard access on the folded card
  (Enter / Space), the Playground entry in the menu and at the X, the kit chip and Fly button in the dock. The scan test
  (`src/scan.test.ts`) now checks the repo's swap-on-scan.
- **Hand-over links** (`?join=`): the repo's flow; after an account switch the kits store is read again, so the new
  account never shows the last one's kits.
- **Documents**: `task.md` and `docs/game-rules.md` are the repo's; one line in the rules says a booth QR now scores in
  full anywhere, which matches the removal of the location check.

## Added for live safety

- **`server/imports.test.ts`**: walks every runtime import reachable from `api/index.ts` and fails on an import without
  `.js`, a missing file, or one outside `server/`, `shared/` and `content/` — the rule behind the 23 September outage.
  It caught this branch's Playground server importing `src/playground/*` (extensionless inside), which would have
  taken the API down on Vercel. Fixed: the numbers the server needs live in **`shared/playground.ts`**, the client
  reads the same ones, and `src/playground/course.test.ts` fails if the course and those numbers drift.
- **Postgres**: the three new tables (`playground_tokens`, `playground_runs`, `playground_state`) are in `SCHEMA`, so
  `PG_SCHEMA` creates them on the first cold start (`CREATE … IF NOT EXISTS`, row-level security on like every other
  table). The DDL as Postgres sees it and every Playground query were read for Postgres; nothing here deletes players,
  so the new foreign keys block nothing. **Not run against Postgres** (no Postgres on this machine): before deploying,
  `MX_TEST_DB=postgres MX_TEST_PG_URL=postgres://… npm test` against a throwaway database is the check.
- **A live bug fixed on the way** (`src/fair/stage.ts`): a frame's timestamp can predate the moment the loop starts, so
  the first time step could be negative; when play began during boot — a booth QR opened with the phone's camera app —
  the camera's settle-in never finished and stayed about 30 m up. Seen on the live build and on the merge; the step is
  now clamped at zero, and the merge settles normally.
